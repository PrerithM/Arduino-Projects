Authentic post-mortems and debugging notes. The interesting part was understanding why things broke.

LAB NOTE #017 HC-SR04 SONAR

Why did my ultrasonic sensor return random 0 cm spikes?

Problem:

Sensor intermittently measured 0 cm or 3000 cm when objects were stationed at a constant 20 cm distance.

Hypothesis:

Echo pin `pulseIn()` timed out or trigger pulse fired before acoustic transducer ring-down settled.

Experiment:

Added a 2µs LOW settling period before 10µs trigger pulse, set timeout to 30ms (5m max limit), and added 5-sample median filtering.

Lesson Learned:

Hardware bugs aren't always hardware bugs. Physics requires transducer dampening time between acoustic bursts.

LAB NOTE #012 TIMING & ASYNC

Why delay() ruins responsive motor control

Problem:

Robot missed bumper collision switches while executing LED blinking routines.

Hypothesis:

`delay()` halts the ATmega328P instruction pipeline completely, ignoring polled digital inputs during sleep.

Experiment:

Refactored loop into non-blocking state machine utilizing `millis()` timestamp differentials.

Lesson Learned:

Never freeze the microcontroller. Treat time as a state variable, not an execution pause.

LAB NOTE #008 POWER & INDUCTANCE

Why DC motors rebooted the Arduino on start-up

Problem:

Engaging full motor speed caused the Arduino Uno power LED to flash and MCU reset immediately.

Hypothesis:

Inductive inrush current dropped 5V rail below brownout detection voltage (BOD threshold 4.3V) + back-EMF spike.

Experiment:

Isolated logic and motor power rails, added 100µF electrolytic decoupling capacitors and flyback diodes across motor terminals.

Lesson Learned:

Always isolate noisy inductive loads from sensitive computational logic. Common ground, separate rails.
