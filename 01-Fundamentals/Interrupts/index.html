Core Architecture

The Interrupt Paradigm

Why software polling fails in high-speed physical computing and how asynchronous hardware interrupts solve it.

🐢

Polling Inefficiency

Repeatedly calling digitalRead() inside loop() burns CPU cycles and misses events if the processor is busy executing a calculation.

⚡

Hardware ISR Vector

Pin transitions flip a hardware gate in 4 clock cycles (~250ns), instantly suspending main execution to service the event handler.

🔒

Volatile Memory

Tells the C++ compiler that variables modified inside an ISR can change asynchronously, forcing memory fetches instead of register caching.

The Core Rule: Keep Interrupt Service Routines (ISRs) minimal. Flag the event, increment counters, and exit immediately (<10µs). Handle heavy processing in the main loop.

⚡ Critical ISR Constraints

NO DELAY() Millis counters rely on Timer0 interrupts, which are disabled during ISRs.

NO SERIAL Serial transmission uses interrupts; calling it inside an ISR risks deadlock.

Microcontroller Firmware Implementation

Production hardware interrupt service routine with debouncing and atomic memory retrieval.

interrupts_basic.ino
/* Minimal Hardware Interrupt Service Routine */

const byte INTERRUPT_PIN = 2;
const byte LED_PIN = 13;

// volatile ensures variable is re-fetched from RAM
volatile bool ledState = false;

void isrToggle() {
  ledState = !ledState;
  digitalWrite(LED_PIN, ledState);
}

void setup() {
  pinMode(INTERRUPT_PIN, INPUT_PULLUP);
  pinMode(LED_PIN, OUTPUT);

  // Attach INT0 on Pin 2 to trigger on FALLING edge
  attachInterrupt(digitalPinToInterrupt(INTERRUPT_PIN), isrToggle, FALLING);
}

void loop() {
  // Main loop can perform heavy tasks without missing button events!
  delay(1000);
}

🔎 Register & API Analysis

1
attachInterrupt(0, fn, FALLING)

Maps ATmega328P external interrupt INT0 to execute the designated ISR when signal drops from 5V to 0V.

2
volatile unsigned long

Informs compiler optimization passes to never store this variable in CPU working registers.

3
noInterrupts() / interrupts()

Creates an atomic critical section when copying multi-byte integers on an 8-bit architecture.

4
micros() inside ISR

Valid for microsecond debouncing delta calculations without causing timer halts.

5
Heavy loop() Delay

Simulates intensive math tasks. Hardware interrupts fire concurrently with zero jitter.

interrupts.ino · production atomic ISR
/*
 * Module: Hardware Interrupt Service Routine (ISR)
 * Features: Debounced ISR + Atomic variable transfer
 */

const byte INTERRUPT_PIN = 2;
const byte STATUS_LED = 13;

volatile unsigned long pulseCount = 0;
volatile bool newPulseFlag = false;

volatile unsigned long lastIsrMicros = 0;
const unsigned long DEBOUNCE_MICROS = 150000;

void isrTrigger() {
  unsigned long currentMicros = micros();
  if (currentMicros - lastIsrMicros > DEBOUNCE_MICROS) {
    pulseCount++;
    newPulseFlag = true;
    lastIsrMicros = currentMicros;
  }
}

void setup() {
  pinMode(INTERRUPT_PIN, INPUT_PULLUP);
  pinMode(STATUS_LED, OUTPUT);
  Serial.begin(9600);

  attachInterrupt(digitalPinToInterrupt(INTERRUPT_PIN), isrTrigger, FALLING);
  Serial.println(F("Hardware Interrupt armed on Pin D2."));
}

void loop() {
  // Simulate heavy computation:
  delay(500);

  if (newPulseFlag) {
    // Atomic copy:
    noInterrupts();
    unsigned long currentCount = pulseCount;
    newPulseFlag = false;
    interrupts();

    Serial.print(F("Interrupt Caught! Total Events: "));
    Serial.println(currentCount);

    digitalWrite(STATUS_LED, !digitalRead(STATUS_LED));
  }
}
